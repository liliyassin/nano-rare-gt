# nanogt Answer Sheet — 2026-06-27

*Mark-scheme answers grounded in the live v4 source (`scoring.py`, `catalog.py`, `mechanism.py`, `natural_history.py`, `cli.py`). 2–5 sentences each.*

---

**1. The two halves of `match_score` (biological fit vs precedent strength).**
Biological fit = `packaging_fit`, `tropism_match`, `modality_compatibility`, `protein_class`, `pathway_similarity`, `inheritance` — how well the *disease's biology* matches what this program does. Precedent strength = `approval_weight` and `immunogenicity` — how validated and clinically usable this *specific* precedent is. Folding both into one ranking number is defensible because both legitimately *vary between candidate programs* for the same disease, so both carry real discriminating information about which precedent is best. That is exactly the property the disease-intrinsic tractability dimensions lack (they're identical across programs), which is why those were split out instead.

**2. `recommend_strategy` output.**
It returns labelled fields: `modality`, `vector`, `route`, `promoter`, `construct`, and a `tractability` summary string. `vector` comes from the top-ranked match (with its program name); `route` and `promoter` are looked up from `_ROA_DATA` / `_PROMOTER_DATA` for the primary tissue; `construct` is "native CDS", "engineered micro/mini-transgene", or "minimal-cassette / dual-AAV" depending on size; `tractability` echoes the disease-level score/tier. When the mechanism is curated "incompatible", `modality` explicitly says NOT gene addition — it names the preferred modality (silencing/editing/RNA), states that no catalog gene-addition precedent applies, and notes the ranking is suppressed. It is labelled a hypothesis/starting point, not a clinical protocol.

**3. Review flags vs confidence.**
Confidence is a purely relative statement — "of the catalog precedents, how good a *match* is this one" — whereas review flags capture translational caveats that rank alone cannot express. So a program can top the ranking with "high" confidence (it really is the closest precedent) while still flagging that the disease needs disease-specific validation before that precedent is usable. Example flags: "LYSOSOMAL MEMBRANE PROTEIN" (cross-correction mechanism of the matched precedent doesn't apply), "MITOCHONDRIAL DNA GENE" (allotopic expression required), "MULTI-SUBUNIT ENZYME", or "Multi-system disease; define a primary therapeutic target tissue." The separation keeps a useful ranking honest about its own limits.

**4. `_APPROVAL_SCORES` ladder.**
approved 1.0; phase3 0.8; withdrawn 0.7; phase2/3 0.7; phase2 0.6; phase1/2 0.5; phase1 0.4; and an unrecognised status defaults to 0.3. `approval_weight` lives in the "precedent strength" half of `match_score` (alongside immunogenicity), not "biological fit", because how far a program has advanced says nothing about how well it fits the *query disease's* biology — it measures how validated/usable that precedent is as evidence that regulators accept the modality. (Note withdrawn 0.7 > phase2 0.6 because Glybera was withdrawn commercially after full approval, so it's still stronger regulatory precedent than an in-progress trial.)

**5. The inheritance dimension.**
(a) A clean AR↔AR or XL↔XL match scores 1.0. (b) A detected dominant-negative allele with no inheritance match scores 0.2 (gene addition alone can't correct a mutant that poisons the wild-type; silencing/editing needed). (c) A haploinsufficient, dosage-sensitive gene scores 0.4 (a second copy may help but constitutive promoters risk overexpression toxicity — e.g. MECP2 duplication is itself pathogenic). It's kept separate from the modality gate because it penalises the *structural* mismatch between inheritance mode and gene-addition logic, while dimension 6 (`modality_compatibility`) handles the curated gene-level mechanism evidence; the two are deliberately independent signals.

**6. `score_tropism` tiers.**
Full 2.0 requires BOTH a vector-tropism overlap with the disease tissues AND the precedent program's stated `tissue_target` directly mentioning a disease tissue. 1.5 = either a direct target match alone, or vector overlap of ≥2 tissues; 1.0 = overlap of exactly one tissue (but the precedent aimed elsewhere); 0.3 = no tissue overlap at all. CNS matching is keyword-expanded: a target counts as CNS if it contains "cns", "brain", "spinal", "motor neuron", or "neuron". If the disease has no tissue annotation, the function returns a neutral 1.0 rather than penalising missing data.

**7. Immune privilege extremes.**
Retina scores highest (1.0) because the blood-retinal barrier plus local immunosuppressive signals (FasL, TGF-β2) strongly limit cytotoxic T-cell access, giving durable transgene expression. Hematopoietic tissue scores lowest (0.3) because immune cells *reside* there — there is essentially no sequestration, so transduced cells face robust surveillance and clearance, requiring conditioning and monitoring. It's a tractability dimension because privilege is a property of the *disease's target tissue*, identical for every candidate program, so it describes how amenable the disease is to durable GT, not how good any one precedent is.

**8. Fabry under mean-tissue aggregation.**
With four annotated tissues (liver, kidney, heart, CNS), v4 averages immune-privilege/promoter/route across all of them instead of inheriting the single most favourable tissue, so kidney's low scores pull the tractability down rather than being hidden behind liver/CNS — a more honest multi-system picture (and it trips the "≥3 tissues: define a primary target" flag). GLA still earns high cross-correction because it is a soluble, secretable lysosomal enzyme: transduced cells secrete it and neighbours recapture it via the M6P receptor. The Fabry heterogeneity flag warns that classic vs late-onset phenotypes have different tissue involvement, so CNS/cardiac delivery requirements vary by phenotype and the scores shouldn't be applied blind to subtype.

**9. Fabry vs Sanfilippo A divergence.**
The driver is the *target tissue / disease distribution*. Fabry is multi-system with major visceral involvement (incl. liver and blood-accessible compartments), so a secreted enzyme delivered to liver or via HSC engraftment can cross-correct systemically — favouring liver/HSC programmes. Sanfilippo A (MPS IIIA) is CNS-predominant, so the binding constraint is crossing into and transducing the brain, which favours a CNS-penetrant AAV9 programme like ABO-101. Mechanistically the divergence acts through `tropism_match` (and the disease-level route/immune-privilege tissue set), not through protein class — both are secretable lysosomal enzymes.

**10. UGT1A1 vs F9.**
UGT1A1 shares with F9 the features that keep it competitive: liver tropism (hepatic AAV5/AAV8 precedents), a small, easily-packaged CDS (~1596 bp), AR/XL loss-of-function inheritance, and strong hepatic promoter/route availability. The weakness is protein class: UGT1A1 (bilirubin UDP-glucuronosyltransferase) is a cell-autonomous, ER-membrane-anchored hepatocyte enzyme — it is not secreted, so it cannot cross-correct neighbouring cells, and every target hepatocyte must be individually transduced. Factor IX, by contrast, is secreted into the bloodstream, so a minority of corrected hepatocytes can supply the whole body — earning F9 both a stronger `protein_class` match and a far higher cross-correction (tractability) score.

**11. The `rank_programs` sort key.**
`-s.match_score` sorts by match score descending (best precedent first); `s.program_name` is an alphabetical tie-break so equal-scoring programs come out in a stable, deterministic order. Hard-failed programs have `match_score = 0.0` and `confidence = "fail"`, so they sink to the bottom — and the CLI/report layers filter them out entirely with `s.confidence != "fail"`. If a program references a serotype missing from the vectors table, `rank_programs` substitutes a safe fallback vector (`cargo_limit_bp: 4700`, empty tropism `"[]"`) so scoring still runs instead of crashing.

**12. `lookup_mechanism` gene-less fallback.**
`load_mechanism_evidence` is `@lru_cache(maxsize=1)` so the CSV is parsed once and reused. When `lookup_mechanism` is called with no gene symbol, it collects all curated records matching the ORPHA ID; if exactly one exists, it returns that record, otherwise it returns the "unknown/missing" evidence. It only fires on a single match because a multi-gene disease would be ambiguous — you can't know which molecular subtype the user means — so those must be scored per gene via `--gene` or `--all-genes` rather than silently picking one.

**13. The multi-subunit enzyme flag.**
It triggers when the gene's keywords or protein name contain subunit markers — "subunit alpha", "subunit beta", "e1 alpha", "e1 beta", "subunit a" — or when keywords contain both "subunit" and "complex". The textbook cohort case is maple syrup urine disease (BCKDHA encodes the E1-alpha subunit of the branched-chain α-ketoacid dehydrogenase complex). The flag tells the user to confirm whether restoring this single subunit reconstitutes full enzymatic activity, or whether co-delivery of the other complex subunits is required — a gene-addition program for one subunit may not rescue the phenotype alone.

**14. Approval vs Phase 3, in regulatory terms.**
A positive Phase 3 demonstrates an efficacy/safety *signal* in a defined trial population, but approval means a regulator (FDA/EMA) has reviewed the full dossier — CMC/manufacturing, complete safety database, benefit-risk, labelling — and accepted the product for marketing in a real population. For a *precedent*-strength score, the relevant question is "have regulators accepted this modality for this indication class?", and only approval answers yes; that is why approved (1.0) outranks a positive Phase 3 (0.8). It's a statement about regulatory validation of the precedent, deliberately distinct from biological fit to the query disease.

**15. Promoter availability: liver/retina vs kidney.**
Liver and retina are the two most heavily pursued in vivo GT targets, so they have large catalogues of clinically validated tissue-specific promoters (liver: ApoE/hAAT, TBG, transthyretin, albumin — used in Hemgenix/Roctavian/DTX301; retina: VMD2, RPGR, GRK1, CRX, IRBP — used in Luxturna/GS010/CPCB-RPE1). Kidney has almost none in clinical use (AQP2, NPHS2 are research-only) partly because little GT has targeted it and the nephron is cell-type heterogeneous. The stated limitation: this dimension scores *availability*, not promoter *strength*, intra-tissue cell-type specificity, or developmental dynamics — so a strong constitutive CAG/CMV promoter scores poorly here despite reliably driving expression. Treat it as a feasibility floor, not a ceiling.

**16. Orphan designation and surrogate endpoints.**
Orphan (drug) designation is a regulatory status granted to therapies for diseases below a prevalence threshold (FDA Orphan Drug Act; EMA equivalent), giving incentives such as market exclusivity, fee waivers, and protocol assistance. A surrogate endpoint is a biomarker or intermediate measure used as a stand-in for a clinical outcome (e.g. circulating Factor IX activity instead of long-term bleed rates, or transgene-derived enzyme level), enabling smaller, faster trials. Both matter for nano-rare diseases that can never power a large randomised trial: nanogt's borrowed-precedent logic leans on the regulatory pathways (orphan incentives, accepted surrogate endpoints) already established by the matched precedent program.

**17. AAV vs ex vivo LV platform tradeoffs.**
IP/licensing: AAV5 is patent-restricted (`freely_available: 0`), so a developer needs a licence/freedom-to-operate, whereas LV is marked freely available in the catalog. Cargo capacity: AAV caps at ~4700 bp (so oversized genes need micro/mini or dual-vector tricks), while LV carries up to ~8000 bp, accommodating larger transgenes. Persistence/integration: LV integrates into the genome (durable in dividing ex vivo HSCs but carries insertional-mutagenesis risk and needs conditioning), while AAV is largely episomal (lower integration risk in vivo, but expression is diluted as cells divide). LV also has the most accumulated clinical experience (20 precedents) for blood/HSC-tractable disorders.

**18. Same precedent + confidence, different tractability.**
Example: Hemophilia B (top precedent Hemgenix, "high" match) sits in an "amenable" tractability tier — liver target, wide therapeutic window, secreted protein with cross-correction, established IV route. A CNS lysosomal disease could also return a "high" match for its best AAV9/LV precedent yet be "conditional/challenging" on tractability — narrow window, harder CNS route, lower cross-correction. The reader must combine them: match answers "which precedent and how good a precedent," while tractability answers "how amenable is this disease to GT at all." A high match on a challenging-tractability disease is a warning that the *closest analogue* still faces disease-intrinsic feasibility hurdles, regardless of how well it ranks.

**19. The packaging CDS fallback.**
`disease_gene.cds_length_bp or program_cds` means that if the query gene's CDS length is unknown (None/0), the scorer silently uses the *precedent program's* CDS size instead. That's optimistic because the precedent program was chosen partly for being packagable (often an already-engineered/small construct), so substituting its size assumes the query gene packages just as easily. If the query disease's true gene is large but un-annotated, this can mask a packaging problem — the program scores a comfortable fit on a number that isn't actually the query gene's size. (`build_review_flags` mitigates this by flagging incomplete gene annotation.)

**20. The stale composite in SUMMARY.md.**
`output/SUMMARY.md` is a v2-era artefact: it reports a single composite score (raw max 21, 46-disease cohort) that the v4 engine no longer computes — v4 produces separate `match_score`/`tractability_score`. The lesson is that generated artefacts drift out of sync with code and must be regenerated and version-stamped, not cited as current; quoting "9.9/10" in the dissertation without noting it predates the split would be indefensible. To regenerate defensibly: first fix the latent bug where `cli.py` (and `report.py`) still reference `s.composite_score`, which no longer exists on the v4 `ScoreBreakdown` and would raise `AttributeError` mid-run — migrate them to `match_score`/`tractability_score` — then re-run `nanogt batch` over the curated cohort and commit the results alongside the engine's commit hash for reproducibility.
